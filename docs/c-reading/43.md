## 主机运行

在仓库根目录执行。Windows 可以将输出名写成 `reading-43.exe`，再从终端运行。

```sh
gcc -std=c11 -Wall -Wextra -pedantic examples/c-reading/43/host_main.c examples/c-reading/43/rx.c -o reading-43
./reading-43
```

先沿 `main()` 预测打印结果，再展开核对。

<details><summary>主机输出与手推</summary>

```text
good=1 bad=1 last=42
good=2 bad=1 last=7 peak=16 dropped=1 gaps=1
```

主机先送一帧正确数据和一帧坏数据。第二轮故意让队列装满并丢掉一个字节，下次入队带上缺口标记，解码器从新帧头恢复。

</details>

## STM32 接线与构建

使用天空星 STM32F407VET6。3.3 V USB 转串口的 TX 接 PA3（USART2_RX，AF7），两端共地。串口设为 115200、8N1，以十六进制发送。固件只接收，已有模板中的 USART1 示例使用 PA9／PA10。

<a href="../../examples/c-reading/43/CMakeLists.txt" download="CMakeLists.txt">下载 CMakeLists.txt</a>

准备 GNU Arm、CMake、Ninja 和 STM32CubeF4 V1.28.3。把固件包路径替换为本机位置。

```sh
cmake -S examples/c-reading/43 -B .work/sky-c-reading-43 -G Ninja -DCUBE_F4_ROOT="D:/SDK/STM32Cube_FW_F4_V1.28.3"
cmake --build .work/sky-c-reading-43
```

复位后以十六进制发送 `00 A5 2A D5 A5 01 00`。在调试器中预期看到 `decoder.good=1`、`decoder.bad=1` 和 `decoder.last=42`。队列峰值 `queue.peak` 随实际时序变化。主机版可确定性复现队列溢出，`queue.dropped` 记录入队失败，`uart_errors` 记录串口外设错误。

芯片资料见 [STM32F407 数据手册](https://www.st.com/resource/en/datasheet/stm32f407vg.pdf) 和 [RM0090 参考手册](https://www.st.com/resource/en/reference_manual/rm0090-stm32f407-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)。
