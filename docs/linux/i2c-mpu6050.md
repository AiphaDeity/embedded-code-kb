# Linux 用 I2C_RDWR 读取 MPU6050 温度

在具备 I²C 控制器的 Linux 板上，给程序一个 `/dev/i2c-N` 路径和模块的 7 位地址。程序先核对 `WHO_AM_I`，唤醒芯片，再将两个寄存器里的补码换算为芯片温度。

## 沿执行路径读代码

1. `main()` 打开设备文件。`read_temperature()` 检查适配器能否执行标准 I²C 事务，再用 `I2C_SLAVE` 检查内核驱动有无占用目标地址。
2. `read_registers()` 通过一次 `I2C_RDWR` 写入寄存器号，紧接着用重复起始读取数据。预计完成两条消息。若只完成一条，程序返回 I/O 错误并丢弃结果。
3. 先读寄存器 `0x75`，只有标识值为 `0x68` 才读取电源设置。`wake_sensor()` 根据电源位退出休眠或循环模式，启用芯片温度传感器。
4. 从 `0x41` 开始连读高、低字节。`FF AC` 还原为 `-84`，按 `raw / 340 + 36.53` 换算后显示 `36.28` °C。

## 连接模块并读取

以开发板原理图或设备树确认 I²C 控制器和板级引脚。外接 3.3 V 兼容的 MPU6050 模块，按模块说明接电源，SCL 和 SDA 各有到 3.3 V 的上拉，板和模块共地。AD0 接低用 `0x68`，接高用 `0x69`。

加载 `i2c-dev` 后，用 `i2cdetect -l` 列出适配器，再确认目标适配器对应的设备文件。下例的 `i2c-1` 仅是命令示例。运行进程需要可读写目标文件，且本实验应独占模块。程序在需要时会修改电源寄存器，采样后芯片保持唤醒。

```sh
mkdir -p .work/linux
cc -std=c11 -Wall -Wextra -Werror -O2 examples/linux/i2c-mpu6050/main.c \
  -o .work/linux/i2c-mpu6050
i2cdetect -l
.work/linux/i2c-mpu6050 /dev/i2c-1 0x68
```

编译需要 Linux UAPI 头文件，例如 Alpine 的 `linux-headers`。成功时打印 `id=0x68`、原始值和摄氏温度。读数反映芯片自身的温度。若 `I2C_SLAVE` 报占用，检查内核绑定；若读 ID 无应答，核对适配器、地址、供电及上拉。

## 练习

**预测题**　AD0 改接高电平。程序参数和 `WHO_AM_I` 分别会变成什么？

<details><summary>核对预测</summary>

程序的地址参数改为 `0x69`。`WHO_AM_I` 仍为 `0x68`，因此身份校验条件继续成立。

</details>

**改动题**　把已有检查程序的两个温度字节改为 `00 00`，再运行测试。

<details><summary>核对改法</summary>

改 `check.c` 的 `TEMP_OUT` 回包，把 `check.sh` 的匹配值改为 `temp_raw=0 temp_c=36.53`。原始值为零时只保留换算公式的偏移量。

</details>

## 验证记录

Alpine WSL 已编译 Linux 程序。链接器替换 `ioctl()` 的主机检查核对了两条组合消息、AD0 高地址、唤醒写入、负值换算、适配器能力不足、地址占用、部分完成和身份不符。目标板实际接线与总线波形待验证。

```sh
cc -std=c11 -Wall -Wextra -Werror -O2 examples/linux/i2c-mpu6050/main.c \
  examples/linux/i2c-mpu6050/check.c -Wl,--wrap=ioctl -o .work/linux/i2c-mpu6050-check
sh examples/linux/i2c-mpu6050/check.sh .work/linux/i2c-mpu6050-check
```
